# SDP-002 — Design Platform Governance

## Purpose

Define ownership, approval and change control for Sengiala design assets.

## Governance model

- Foundation maintainers approve architecture and breaking changes.
- Contributors propose changes through pull requests.
- Every change identifies affected SDS, SDT and SDC artefacts.
- Accessibility, compatibility and migration impact are reviewed before release.
- Approved decisions are versioned and recorded in release documentation.

## Change classes

- Patch: clarification or compatible correction.
- Minor: additive token, standard or component.
- Major: breaking naming, behaviour or package contract.
